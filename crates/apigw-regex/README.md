# apigw-regex

`java.util.regex` semantics on top of `fancy-regex`, for API Gateway mapping templates,
integration response selection patterns, and Lambda authorizer identity validation expressions.

Java's regex engine differs from Rust's in ways that change results: `\w`, `\d`, `\s`, and `\b`
are ASCII by default, `.` and `$` know about line terminators beyond `\n`, `matches()` covers the
whole input, and replacement strings use `$n` with greedy group numbers. This crate parses Java
pattern syntax, translates it to an equivalent `fancy-regex` pattern, and provides Java's
`matches`, `find`, `replaceAll`, `replaceFirst`, and `split`. It is a pure library with no I/O.

```rust
use apigw_regex::{JavaRegex, Replacement};

let regex = JavaRegex::new(r"(?<user>\w+)@example\.com")?;
assert!(regex.matches("ann@example.com")?);
let redacted = regex.replace_all("mail ann@example.com", &Replacement::from("${user}@***"))?;
assert_eq!(redacted, "mail ann@***");
```

Patterns Java rejects fail with `RegexError::Syntax`; patterns Java accepts but that cannot be
translated faithfully (only `\N{name}`) fail with `RegexError::Unsupported`. Matching is bounded
by a backtrack limit and reports `RegexError::BacktrackLimitExceeded` rather than "no match".

The crate docs (`cargo doc -p apigw-regex --open`) list the known differences from Java, and
[docs/regex-engine.md](../../docs/regex-engine.md) explains the design.

## Tests

```bash
cargo test -p apigw-regex
```

`tests/fixtures/java-regex.jsonl` is generated by running real `java.util.regex` (JDK 21) with
[`tools/java-regex-oracle`](../../tools/java-regex-oracle); `src/tables.rs` comes from the same
tool. `tests/never_panics.rs` is a proptest, and `fuzz/fuzz_targets/java_regex.rs` fuzzes the
parser and matcher.
